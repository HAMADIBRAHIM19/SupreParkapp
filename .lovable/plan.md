# تسجيل موقع إنشاء الحساب

## الوضع الحالي
جدول `profiles` لا يحتوي أي حقول موقع، وصفحة التسجيل ترسل فقط اسم المستخدم والاسم الكامل ونوع الحساب. لذلك لا يمكن حالياً معرفة موقع إنشاء الحساب لأي مستخدم — بما في ذلك المسجّلين مسبقاً (62 مستخدم)، لأنه لا يوجد أي سجل IP محفوظ.

## الحل المقترح
تسجيل الموقع تلقائياً من عنوان IP عند إنشاء الحساب (دولة + مدينة)، بدون طلب إذن الموقع من المستخدم.

### 1. حقول جديدة في قاعدة البيانات
إضافة إلى `profiles`:
- `signup_country` (رمز الدولة + الاسم)
- `signup_city`
- `signup_ip_hash` (بصمة مشفّرة للـ IP، بدون تخزين IP كامل لأسباب الخصوصية)

### 2. دالة خدمية على الـ backend
دالة `record-signup-location` تُنادى مرة واحدة بعد نجاح التسجيل:
- تقرأ IP الطالب من رؤوس الطلب
- تستدعي خدمة GeoIP لتحديد الدولة والمدينة
- تحدّث سجل الملف الشخصي للمستخدم الحالي فقط

### 3. تحديث صفحة التسجيل
بعد `signUp` الناجح تُستدعى الدالة بصمت (فشلها لا يعطّل التسجيل).

### 4. العرض في لوحة الأدمن
تبويب جديد "المستخدمون" في `/admin` (محمي بدور admin):
- جدول: الاسم، اسم المستخدم، نوع الحساب (باحث/طاقم)، الدولة، المدينة، تاريخ التسجيل
- فلترة بنوع الحساب وبالدولة
- زر تصدير CSV

### 5. المستخدمون الحاليون
تُترك حقول الموقع فارغة وتظهر كـ "غير معروف" — لا توجد بيانات سابقة يمكن استنتاجها.

## تفاصيل تقنية
- migration لإضافة الأعمدة (لا تغيير على سياسات RLS الحالية للملف الشخصي؛ الأدمن يقرأ عبر دالة الأدمن الآمنة).
- سياسة قراءة للأدمن على `profiles` باستخدام `has_role(auth.uid(),'admin')` لعرض القائمة.
- الدالة تعمل بمفتاح الخدمة وتتحقق من هوية المستخدم عبر التوكن قبل الكتابة.
- خدمة GeoIP مجانية بدون مفتاح؛ إن فشلت يُحفظ الحقل كـ NULL.
- إضافة ملاحظة في صفحة الخصوصية بأن الدولة/المدينة تُسجَّل عند إنشاء الحساب.
